# 项目概览与架构

## 定位

ChroStar 是 LSPosed 模块，包含两部分：

- `module/app`：Android 应用与 Compose 设置页，负责配置、调试和能力状态展示。
- Hook 侧：注入 Google Chrome 后按引擎版本安装功能 Hook。

## 入口与加载

`HookEntry.handleLoadPackage` 是 Xposed 入口。Chrome 152+ 可能将实现类放在 isolated split 中，因此入口先挂 `Application.attach`、`createContextForSplit` 与 `Instrumentation.callActivityOnCreate` 探测；split ClassLoader 就绪后统一安装主体 Hook，并使用一次性门禁避免重复安装。

## 引擎路由

| 引擎 | 路由 |
|---|---|
| Chrome 145 | 大版本隔离 + 已验证旧短名路径 |
| Chrome 152 / 153 | 独立指纹；指纹失败时切换结构解析 |
| Chrome 154+ | 公开锚点结构解析 + DexKit 语义查询 + 运行时验证 + versionCode 缓存 |

解析链为：进程内缓存 → 磁盘缓存 → 锚点结构解析 → DexKit 补缺 → 已知版本数据表 → fail-closed。缓存条目必须通过类加载与方法签名校验；Chrome versionCode 或 schema 变化会失效。

## 配置系统

配置按 Chrome 大版本使用 `v{major}.{key}` 独立建档。首次遇到新版本时按“同名档 → 最近使用档 → 旧全局键 → 默认值”迁移，旧全局键只读不删除。

Hook 侧读取顺序：

1. New XSharedPreferences
2. ConfigProvider
3. 旧 XSharedPreferences
4. 默认值

设置页与 Hook 侧共用键常量和档案读取规则，避免版本间配置串扰。

## 功能模块

- `HomeCleaner`：启动、恢复、新标签页与历史标签清理。
- `DownloadSafetyBypass`：六类下载弹窗与版本化原生事件 ID。
- `AutoInstallApk` / `OverwriteAndAutoOpen`：下载完成自动打开、扩展类型与自定义后缀。
- `BannerController`：下载完成横幅替换 Toast、翻译横幅隐藏与跨回调去重。
- `DownloadDirRedirect`：自定义下载目录。
- `LocationAndDiagnostics` / `LogTail`：配置诊断、能力状态与日志尾部。

完整构建与检查命令见根目录 `README.md`。

## 验证原则

静态结构解析、依赖下载和编译成功都不能替代真机验证。每个能力必须记录引擎版本、验证状态与未验证范围；无法确认的弹窗 ID 或符号能力必须 fail-closed。
